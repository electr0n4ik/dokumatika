# Докуматика

Сайт `dokumatika.ru`: бесплатный генератор политики конфиденциальности по 152-ФЗ
и платный комплект документов для оператора персональных данных — 799 ₽.

Бесплатная часть приводит поисковый трафик, платная зарабатывает. Продукт держится
на одном факте: с 01.09.2025 согласие на обработку ПД должно быть отдельным
документом, поэтому одной политики (что дают бесплатные генераторы) уже мало.

Технически: Python 3.10+ на чистой стандартной библиотеке, SQLite, ванильный JS.
Ни pip-зависимостей, ни сборщика, ни внешних запросов со страниц.

## Быстрый старт

```bash
git clone https://github.com/electr0n4ik/dokumatika.git
cd dokumatika
cp .env.example .env        # заполнить SELLER_*, при необходимости ROBOKASSA_*
make run                    # http://127.0.0.1:8081/
```

Виртуальное окружение и `pip install` не нужны — приложению хватает стандартной
библиотеки Python 3.10+. `make` без аргументов покажет остальные команды.

Если системный `python3` старее 3.10, укажите интерпретатор явно:
`make run PYTHON=python3.12` (Makefile проверит версию и скажет об этом сам).

Пока `ROBOKASSA_*` не заполнены, оплата просто выключена: генератор, страницы и
админка работают. Пока не заполнены `SELLER_*`, оферта показывает предупреждение
вместо реквизитов.

## Тесты и проверки

```bash
make test     # pytest
make check    # ruff + проверка синтаксиса + тесты (перед коммитом)
```

Инструменты разработчика ставятся один раз глобально:
`pip install pytest ruff black`. На боевом сервере они не нужны.

## Выкатка

Чистый Debian 12 или Ubuntu 22.04+, от root, одна команда:

```bash
apt update && apt install -y git
git clone https://github.com/electr0n4ik/dokumatika.git /root/dokumatika
bash /root/dokumatika/scripts/bootstrap.sh dokumatika.ru
```

Скрипт ставит пакеты, заводит системного пользователя, раскладывает код в
`/opt/dokumatika` и базу в `/var/lib/dokumatika`, **сам генерирует
`ADMIN_TOKEN` и `INDEXNOW_KEY`**, создаёт swap, ограничивает журналы, ставит
юниты systemd с ежедневным бэкапом и сверкой платежей, настраивает nginx под
переданный домен и получает сертификат Let's Encrypt. В конце печатает адрес
админки с токеном и список того, что осталось заполнить руками.

Единственный вопрос — подтверждение в самом начале (`-y` пропускает его).
Повторный запуск безопасен и служит обновлением кода: `.env` сохраняется,
секреты не перегенерируются, `ASSET_VERSION` поднимается сама — поэтому забыть
про неё после правки `styles.css` или `js/*.js` невозможно.

Единственное, чего скрипт сделать не может, — направить A-запись домена на
сервер. Если DNS ещё не готов, скрипт настроит всё остальное, объяснит проблему
и предложит повторить запуск.

Проверка боевого сайта после выкатки:

```bash
bash scripts/smoke_prod.sh dokumatika.ru   # коды ответа, TLS, заголовки, /admin/, база
make preflight                             # реквизиты и ключи (локально)
```

Что от владельца требуется лично — купить домен, направить DNS, пройти
модерацию Robokassa, вписать свои реквизиты, подать уведомление в РКН — с
оценкой в минутах перечислено в начале
[`deployment/ROLLOUT.md`](deployment/ROLLOUT.md). Там же подробные ручные шаги
на случай отладки и раздел «Эксплуатация».

## Robokassa

Подробная инструкция — [`docs/robokassa.md`](docs/robokassa.md). Главное:

1. В ЛК «Мои магазины» → «Технические настройки» указать адреса (метод POST):
   - Result URL — `https://dokumatika.ru/robokassa/result`
   - Success URL — `https://dokumatika.ru/oplata/uspeh/`
   - Fail URL — `https://dokumatika.ru/oplata/otmena/`
2. **Алгоритм хеширования в кабинете и `ROBOKASSA_HASH_ALGORITHM` в `.env` должны
   совпадать.** По умолчанию в кабинете стоит MD5; расхождение даёт ошибку 29
   («неверная подпись»), и это самая частая причина «оплата не работает».
3. Password #1 и Password #2 — в `.env`, тестовые пароли отдельной парой.
   Проверить связку можно с `ROBOKASSA_TEST_MODE=1`: деньги не списываются.
4. Чеки для самозанятого делают «Робочеки СМЗ» — бесплатный сервис Robokassa,
   его нужно разрешить в приложении «Мой налог».
5. Robokassa проверяет сайт перед подключением: должны быть публичные оферта,
   политика обработки ПД, порядок возврата, контакты и реквизиты в подвале
   («Самозанятый, ФИО полностью, ИНН, город»).

## Что дальше

1. Заполнить `SELLER_*` в `.env` и прогнать `make preflight`.
2. Подключить Robokassa, проверить оплату в тестовом режиме, потом боевым платежом
   на 799 ₽ самому себе (деньги вернутся за вычетом комиссии).
3. Задать `METRIKA_ID` и `INDEXNOW_KEY`, после каждой публикации страниц —
   `make indexnow`.
4. Поставить `make backup` в cron (база маленькая, бэкап дешёвый).
5. Смотреть воронку в `/admin/`: посещения → запуск визарда → скачивание политики →
   переход к оплате → продажа. Решение «усиливать или замораживать проект»
   принимается по этим числам, а не по ощущениям.

## Ограничения, о которых нельзя забывать

- Сервис формирует **типовые шаблоны** и не является юридической консультацией.
  Формулировки «одобрено Роскомнадзором», «гарантия отсутствия штрафов», «100%
  соответствие» недопустимы — это нарушение ст. 5 ФЗ «О рекламе».
- Все цифры штрафов и норм берутся из `docs/fakty-152-fz.md`. КоАП и 152-ФЗ
  меняются часто: перед правкой текстов сверяйтесь с первоисточником.
- Ответы визарда и реквизиты пользователя не уходят на сервер и нигде не
  хранятся. Это не только приватность, но и отсутствие у нас обязанностей
  оператора по этим данным.
