# CLAUDE.md — контракт проекта «Докуматика»

Файл читается в начале каждой сессии. Здесь то, что нельзя вывести из кода за
разумное время, и то, нарушение чего ломает проект юридически или по деньгам.

## Что это

`dokumatika.ru` — сайт из двух частей:

1. **Бесплатный генератор политики конфиденциальности по 152-ФЗ.** Визард из
   пяти шагов, документ собирается в браузере, приманка для поискового трафика.
2. **Платный комплект документов — 799 ₽** (согласия, cookie-политика, приказ о
   назначении ответственного, форма отзыва, журнал обращений, памятка по
   уведомлению в РКН). Оплата — Robokassa, владелец — самозанятый в РФ.

Продающий факт, ради которого всё построено: с 01.09.2025 согласие на обработку
ПД должно быть **отдельным документом**, поэтому одной политики (что дают
бесплатные конкуренты) закону уже недостаточно.

## Команды

```bash
make run        # dev-сервер, PYTHONPATH=src python3 -m app.server
make test       # PYTHONPATH=src python3 -m pytest tests -q
make check      # ruff + синтаксис + тесты — перед каждым коммитом
make preflight  # проверка готовности к бою (реквизиты, ключи, права на var/)
```

`make` без цели печатает список команд. Настройки — в `.env` (шаблон
`.env.example`); приложение читает только переменные окружения.

## Стек — не обсуждается

- Python **3.10+, только стандартная библиотека**. Ни одной pip-зависимости в
  рантайме. `pytest`/`ruff`/`black` — инструменты разработчика, на сервере их нет.
- Сервер: `http.server.ThreadingHTTPServer`. Шаблонизатора нет — HTML собирают
  функции на Python.
- База: SQLite. Клиент: ванильный JS, без сборщика, без npm, без CDN.
- **Ноль внешних запросов со страниц**: шрифты системные, библиотеки не
  подключаются. Единственное исключение — счётчик Метрики, и только если задан
  `METRIKA_ID`.

Предлагать Flask/FastAPI/Jinja/PostgreSQL/React не нужно — решение принято под
сервер 2 vCPU / 4 GB, где рядом живут другие проекты.

## Архитектура

```
Браузер ──HTTPS──► nginx ──proxy_pass──► app :8081 ──► SQLite (var/dokumatika.sqlite3)
   │                (TLS, gzip,          (один процесс
   │                 rate limit,          ThreadingHTTPServer,
   │                 статика, заголовки)  слушает 127.0.0.1)
   │
   └── визард и генерация документов работают ЗДЕСЬ, ответы никуда не уходят

Robokassa ──POST──► /robokassa/result  (единственный источник статуса «оплачено»)
```

Порт: в коде по умолчанию 8080, в `.env` и systemd проекта — **8081** (8080 занят
соседним сайтом на том же сервере). Значение должно совпадать в трёх местах:
`.env`, конфиг nginx, unit systemd.

## Инварианты — нарушать нельзя

1. **Ответы визарда и реквизиты пользователя НИКОГДА не уходят на сервер.**
   Документы собираются в браузере. Сервер хранит по заказу только код продукта,
   сумму, email доставки и статус. Любой код, отправляющий ответы визарда на
   бэкенд, — регресс: он делает нас оператором чужих ПД со всеми обязанностями
   по хранению, защите и удалению.
2. **Статус «оплачено» ставит только `ResultURL`** — и только после проверки
   подписи на Password #2. `SuccessURL` не верит ничему: пользователь способен
   открыть его руками с любыми параметрами. Страница успеха лишь показывает уже
   выставленный статус.
3. **Сумма берётся из каталога продуктов**, а не из запроса. Иначе подмена
   `OutSum` в форме оплатит комплект за рубль. Пришедшую сумму сверяем со своей
   записью, а не доверяем ей.
4. **Весь текст интерфейса, документов и комментариев — по-русски.**
5. **Правка `styles.css` или любого `js/*.js` требует нового `ASSET_VERSION`.**
   Статика отдаётся с кэшем на год по версионированному URL — без смены версии
   посетитель останется на старом файле.
6. **Никогда не заявляем** «юридическая консультация», «одобрено Роскомнадзором»,
   «гарантия отсутствия штрафов», «100% соответствие». Только «типовой шаблон»,
   «конструктор», «автоматизированная подготовка документов» — с видимым
   дисклеймером на страницах генератора (ст. 5 ФЗ «О рекламе»).

Дополнительно, из тех же соображений:

- Любой текст в HTML проходит через `esc()`. Сырой HTML — только через `Raw()`
  и только для наших литералов, никогда для пользовательского ввода.
- В логи не попадают ПД и секреты: email маскируется, подписи и пароли не пишутся.
- Все цифры штрафов и норм — из `docs/fakty-152-fz.md`. Факта нет в файле —
  значит, его нет на сайте. Ничего не додумывать.
- Движок шаблонов реализован дважды (Python и JS) и должен давать одинаковый
  результат. Поэтому язык условий нарочито примитивен — `{field, op, value}`.
  Любой «полноценный DSL» немедленно разведёт две реализации.

## Правила кода

- `from __future__ import annotations` вверху каждого модуля, аннотации типов
  обязательны.
- Длина строки — до 110 символов (`ruff`, `black`).
- Комментарии — только о неочевидном: почему так, а не что делает строка.
  Комментарии к самоочевидному коду не нужны.
- Стиль — как в уже написанных модулях: модульный docstring объясняет решение,
  а не пересказывает имена функций.
- Новая страница = файл в `src/app/web/pages/` с объектом `PAGE` + строка в
  `pages/__init__.py`. Роутер и `sitemap.xml` соберутся сами. Функция `build`
  обязана быть чистой: без БД и сети, иначе страницу нельзя протестировать.
- Тесты не поднимают сервер и не ходят в сеть; фикстуры — в `tests/conftest.py`.
